# Plan the Onboarding

## When To Use
Ramp-up takes months and stakeholders blame the talent. Meanwhile the new hires finished every module on the list and still hand the awkward cases to whoever sits nearest. Use this to plan the job-skill part of onboarding for one role. It answers: which real tasks must a new hire handle, in what order, with whom beside them, and how does anyone know they are ready for each one?

## When Not To Use
If you are sequencing modules for several roles, run Map the Curriculum. If an established employee needs a manager's support around one course, Brief the Managers is enough. This skill is one role's first weeks.

## Inputs
- The role and its real tasks, with the exceptions that trip people up (your task breakdown or expert notes, if they exist)
- The onboarding content you have today (modules, policies, system access steps), who could be a buddy, by role, and how long the path should run
If you have none of this, I start from the role and five tasks you list from memory and mark the output as a first draft.

## Approach
The four Cs of onboarding from the SHRM Foundation's public guideline (compliance, clarification, culture, connection) for the frame, and practice on real problems (Merrill, 2002) for the job-skill part. The guideline covers onboarding broadly, so the tasks carry the plan and the four Cs check that nothing is missing. The failure this prevents: first weeks of policy reading and system tours, every box ticked, then a first live exception met alone, with the buddy on leave and the answer in a module from day two.

## Workflow
1. Ask up to three questions: which tasks a new hire must handle alone and by when, which exceptions cause the most trouble, and who does the work well today, by role.
2. List the real tasks and order them from simpler to harder: the usual case, then the common exceptions, then the rare costly ones. Take them from the task breakdown if you have it. A task nobody can describe yet goes back to the expert.
3. Lay out the weeks over a length you set. Each week names the tasks in focus, the practice that comes before the live task (a scenario from real cases), and which of the four Cs it covers. Compliance sits where the work needs it, not all in week one.
4. Place clarification and culture in the weeks where the tasks show them: what "good" looks like in this role, said plainly, at the moment the new hire can see it.
5. Plan connection: buddy sessions at a cadence you set, each tied to a task that week. Watch, then do together, then do while the buddy watches. Booked in the calendar, never "when there is time".
6. Set sign-off per task: the new hire does it with a person beside them, who confirms readiness to do it alone or names what to practise next. Never a quiz, never a score, and no new hire is compared with another.
7. List compliance and policy items apart. What is required, and by when: check with a qualified adviser.

## Output Format
```markdown
# Onboarding Path
Role: [role] | Length: [weeks you set] | Path owner: [role] | Buddy: [role]
## The real tasks, simpler to harder
| No. | Task | Usual case, common exception or rare costly one | Week it is first done live | Source |
|---|---|---|---|---|
| [1] | [task] | [type] | [week] | [task breakdown / expert / "ask the expert"] |
## Week by week
| Week | Tasks in focus | Practice before the live task | Four Cs covered | Buddy session (date, task, watch / together / observed) |
|---|---|---|---|---|
| [1] | [tasks] | [scenario from a real case] | [compliance / clarification / culture / connection] | [session] |
## Sign-off by doing the task
| Task | Done with | Date | Ready to do alone, or what to practise next |
|---|---|---|---|
| [task] | [role] | [date] | [ready / practise ...] |
## Content with no task, and compliance items
Cut or moved to reference: [module or document, and the call]
Compliance and policy items: [policy or rule, week, owner], each one marked "check with a qualified adviser"
## Decision
[Hiring manager name] and [L&D lead name] approve the task order, the buddy time and who signs off each task by [date].
```

## Done When
- Every task sits in a week, ordered from simpler to harder, exceptions included
- Every week has practice before the live task and a booked buddy session
- Each of the four Cs appears somewhere in the path
- Every sign-off is done by doing the task with a person, and no column holds a score

## Quality Bar
- Modules serve tasks; a module tied to no task is cut or moved to reference
- Lengths and cadences are yours; the path states no benchmark ramp-up time
- A new hire who is not ready yet gets "what to practise next", in words, from the person beside them
- Legal and policy items say "check with a qualified adviser"
- Sign-off is readiness for a task, agreed with a person beside the new hire; it never grades or ranks them.
