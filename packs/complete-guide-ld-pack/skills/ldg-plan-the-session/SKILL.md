# Plan the Session

## When To Use
A virtual session competes with email and chat from minute one, and the agenda you have is a list of topics with a slide count beside each. Use this when the objectives and the content exist and you need a flow where people do the task inside the session, not after it. It answers: what happens in each block of time, how long does it get, and where do people practise?

## When Not To Use
If the only objective is still "understand the topic", run Write the Objectives first, because a flow built on a vague objective is a lecture with breaks. If another trainer will deliver the session, this plan is only the skeleton and Write the Facilitator Guide says what they say and do.

## Inputs
- The objectives, the audience by role and number, the format (in the room or virtual) and the total time.
- The content or slides you already have, and any real cases, messages or mistakes the expert gave you.
If you have none of this, I start from the topic, the role and the time slot and mark the output as a first draft.

## Approach
Gagné's nine events of instruction (a university teaching-centre page), grouped into five blocks, with Merrill's First Principles (2002 paper) for the opening: start from a real problem, not the agenda. The judgement is about time. Showing always overruns, so the plan fixes the practice time first and lets the content fit around it. The failure it prevents: the trainer is still on the background section when the break arrives, the exercise shrinks to a show of hands, and the chat window is the only place anyone took part.

## Workflow
1. Ask at most three questions: what should people be able to do at work after this session, how long is it and is it in the room or virtual, and what real problem from the job can it open with?
2. Lay the nine events into five blocks. Open: gain attention, inform of objectives. Recall: stimulate recall of prior learning. Show: present the content, give guidance. Practise: elicit performance, give feedback, assess performance. Apply: retention and transfer. Every objective must land in a Practise block; if one does not, say so before timing anything.
3. Write the first five minutes: a real case, message or mistake from the job that people react to before any agenda slide. The objectives come after, in one line, as what people will be able to do.
4. Time each block and show the slack. You set the split between showing and practising. If the content does not fit the Show time, list what to cut or move to a handout; practice time is never the buffer.
5. Give each block one activity line and its materials. Each Practise block carries the pointer "activity card to come"; the detail belongs in the group work cards. For a virtual session, add an interaction at an interval you set, named by type (poll, chat answer, breakout, shared document).
6. Write "assess performance" as feedback in the room: the trainer or peers comment on the work produced. Nothing is noted against a person.
7. Close on transfer: each person writes what they will try at work, and when, and keeps the note.

## Output Format
```markdown
# Session Plan
Session: [title] | Audience: [role, number] | Format: [in the room / virtual] | Length: [minutes]
After this session people can: [objective] / [objective]
## First five minutes
Real problem shown: [case, message or mistake from the job]
Question put to the room: [question] | How people answer: [aloud / chat / in pairs]
Objectives in one line, said after: [line]
## Timed flow
| Start | Block | Events it carries | Objective served | Activity (one line) | Materials | Virtual interaction |
|---|---|---|---|---|---|---|
| [00:00] | Open | Attention, objectives | [objective] | [activity] | [materials] | [type or none] |
| [time] | Recall | Prior learning | [objective] | [activity] | [materials] | [type] |
| [time] | Show | Content, guidance | [objective] | [activity] | [materials] | [type] |
| [time] | Practise | Performance, feedback in the room | [objective] | [activity card to come] | [materials] | [type] |
| [time] | Apply | Retention and transfer | [objective] | [what I will try at work, and when] | [materials] | [type] |
## Time budget
Show: [minutes] | Practise: [minutes] | Split set by: [name] | Slack: [minutes, and where it sits]
If showing overruns, cut or move to a handout: [content, in order]
## Decision
[Trainer or L&D lead] confirms the flow and the show to practise split by [date], before the group work cards and the slides are built.
```

## Done When
- Every objective has a Practise block where people do the task, not only hear about it.
- The first five minutes open on a real problem from the job, before the agenda.
- The timings add up to the session length, with the slack visible.
- The session closes with each person naming what they will try at work, and when.

## Quality Bar
- Every duration, interval and split is a [placeholder] you set; the plan states no norm for attention spans.
- Activities fit the format: a virtual block names the interaction type, never a product.
- A block has one line of activity here; anything longer belongs on a group work card.
- Claude drafts the plan; the trainer runs the room and changes it, and nothing a participant does in the session is recorded against them.
